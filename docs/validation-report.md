## 依赖安全审计

经用户授权后，使用 NuGet 官方源对解决方案的直接与传递依赖执行安全公告查询。
首轮发现 `SQLitePCLRaw.lib.e_sqlite3 2.1.6` 命中一个高危公告
[`GHSA-2m69-gcr7-jv3q`](https://github.com/advisories/GHSA-2m69-gcr7-jv3q)；
测试工程另有两个只存在于旧测试工具依赖链中的高危包。

本轮采用最小兼容修复：保留 `Microsoft.Data.Sqlite 8.0.21`，将原生 SQLite bundle
显式固定到 `SQLitePCLRaw.bundle_e_sqlite3 2.1.12`，并升级测试 SDK、xUnit 与覆盖率
收集器。重新从 NuGet 官方源恢复后，Core、App、Tests 均报告没有已知漏洞；随后
严格构建、345 项测试、自包含发布、单实例黑盒及 65 秒静默复测均通过。仓库同时
启用了直接与传递依赖审计，今后 `NU1901`～`NU1904` 会阻止构建或发布；仅公告源
暂时无法连接的 `NU1900` 保持为可见警告，避免离线开发被误锁死。

## 限额窗口兼容性

OpenAI [当前官方定价文档](https://learn.chatgpt.com/docs/pricing)仍描述五小时窗口，
并说明可能同时存在周限制；官方 [Codex App Server 协议](https://learn.chatgpt.com/docs/app-server)
则公开了 `account/rateLimits/read`、变更通知、多 bucket 结果，以及
`usedPercent`、`windowDurationMins`、`resetsAt` 等字段。

本机只读证据显示：正式索引中曾记录 3,215 个 300 分钟窗口，时间范围为
2026-06-17 22:18 至 2026-07-11 22:04（Asia/Shanghai）；10080 分钟窗口仍持续
出现。最近日志只返回周窗口，短窗口为空。这说明当前账户的客户端行为与官方通用
文档并不完全同步，但并不代表接口或五小时窗口已经永久移除。

现有模型、日志解析器和窗口命名逻辑已能同时处理 primary/secondary、300 分钟与
10080 分钟窗口，收起态也会采用剩余量更紧张的窗口。当前未绑定的是“同时明确列出
两个窗口”的独立 UI，也未引入额外 App Server 进程。建议保持低资源日志路径，先
做“300 分钟窗口存在时才显示、缺失时完全折叠”的条件 UI；只有未来日志不再提供
恢复后的短窗口，才评估接入 App Server。这样现在不产生额外轮询或常驻开销。

## 本地异常诊断

未知后台异常、未观察任务异常、启动异常和 Dispatcher 异常会以尽力而为方式写入：

## 隐私与联网检查

源码未发现 `HttpClient`、WebRequest、Socket、遥测、上传或下载路径，运行时不主动
