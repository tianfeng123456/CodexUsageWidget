# 低资源性能验证

本页记录低资源复测方法、已有历史样本及其适用边界。结果必须注明是否预先打开过
“每日周额度”浮层；基础收起静默与“先查询浮层再收起”的静默不是同一个用例，
不能互相替代。任何结果只对报告中记录的 EXE SHA-256 有效。

机器可读历史结果保存在 [`idle-performance-previous-candidate.json`](idle-performance-previous-candidate.json)。可重复采样脚本为 `scripts\measure-idle.ps1`，它会拒绝已有组件进程，启用 Per-Monitor DPI 感知，枚举目标进程可见 HWND，并按 `-CollapsedMode Circle|Capsule` 硬校验 80×80 或 208×80 待机态，在索引稳定后才开始计时。

当前证据状态：

- 当前 Vision Glass 圆环与胶囊基础静默：A2FB25… 哈希均硬通过，
  `databaseWritesObserved=false`、`validationPassed=true`。
- 当前每日周额度预热后静默：A2FB25… 哈希完成窗内浮层打开/关闭并由
  420×540 回到 80×80，随后 65.019 秒硬通过，
  `databaseWritesObserved=false`、`validationPassed=true`。
- Vision Glass 不使用原生 Acrylic。桌面背景只在界面事件触发时抓取一次，
  软件模糊在后台线程完成并冻结为静态图像；没有持续抓屏、持续模糊、渲染循环或
  固定刷新计时器。当前两种待机基础静默和周额度预热后静默数值见上表。
- 玻璃透明度 0～100 仅改变玻璃背景层合成强度，文字、图标和状态色不参与淡出；
  设置页拖动只即时重绘已有表面，不触发日志读取、周期统计或 SQLite 刷新，也未
  增加待机计时器。
- 早先记录的持续日志活动 CPU 样本可用于趋势参考，但不冒充当前玻璃 EXE 的重新
  认证结果。

本报告的自动采样范围是进程 CPU、内存、窗口尺寸/DPI 与数据库文件变化；未采集 GPU 占用，也未使用 ETW 统计内核唤醒。因此“无持续 CPU 回归”和“正式观察期 SQLite 零写入”只在上述实测范围内成立，不外推为 GPU 或内核唤醒结论。

## 收起静默 65 秒

1. 使用最终 Release EXE 和已经完成初始索引的 Codex Home。
2. 启动后等待后台初始化结束，将窗口取消固定并收起；测试期间不产生新 Codex 日志、不移动鼠标、不打开设置。
3. 先静置 10 秒，再连续采样至少 65 秒。记录进程 `TotalProcessorTime`、`PrivateMemorySize64`、`WorkingSet64` 和 I/O 计数。
4. 同时使用 Process Monitor 或等价 ETW 工具，仅过滤 `CodexUsageWidget.exe`，观察：
   - `usage-index-*.db`、`-wal`、`-shm`；
   - `sessions` 与 `archived_sessions`；
   - 固定约 30 秒出现的重复访问。
5. 通过标准：没有周期排行查询或 SQLite 写入，没有固定 30 秒访问脉冲；无日志变化时不应发生额度尾读。

CPU 按“单核 100%”计算：

```text
CPU% = 进程 TotalProcessorTime 增量 / 墙钟时间增量 × 100
```

如需换算为任务管理器式整机百分比，再除以逻辑处理器数。报告必须注明使用的口径。

## 每日周额度预热后的静默

该用例验证用户主动查询七天周额度趋势后，应用回到收起态仍不会周期查询或写库。
当前最终样本通过真实指针从圆环悬停展开，再用 UI Automation 打开和关闭浮层，
最后收起回到圆环：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\measure-idle.ps1 `
  -PrimeWeeklyQuotaOverlay `
  -AutomationTimeoutMilliseconds 30000 `
  -DurationSeconds 65 `
  -CollapsedMode Circle `
  -OutputPath .\docs\idle-performance-weekly-final.json
```

当前 Vision Glass EXE 已完成该用例。机器可读证据见
[`idle-performance-weekly-final.json`](idle-performance-weekly-final.json)：
Overlay 在同一 420×540 主窗内打开和关闭成功，随后重新收起为 80×80；稳定确认期
及 65.019 秒正式观察期的 DB、WAL、SHM 均无变化。正式观察消耗
0.125 CPU 秒，单核 / 整机口径分别为 0.1923% / 0.0120%。热身阶段因主动查询
与索引补齐发生数据库变化是预期行为，不计入稳定期和正式观察期的零写入判定。

该预热方法不能替代 `capture-ui.ps1` 对真实悬停、拖动和移出的综合验收。若测试环境需要从固定展开状态启动，也可额外传入
`-PrimeFromPinnedStartup`；无论采用哪种启动路径，脚本都会在正式采样前确认窗口已经恢复为 80×80。

## 持续日志写入

1. 保持组件收起，通过正常 Codex 会话让一个活动 `.jsonl` 持续追加；不要为测试手工破坏真实日志。
2. 在 Process Monitor 中记录组件读取的文件、偏移和字节数，同时记录每次额度 UI 变化时间。
3. 验证 watcher 只登记发生变化的日志路径；静默约 1.5 秒后处理，写入持续不断时相邻处理不超过约 3 秒。
4. 验证读取集中在变化文件新增尾部，不重新枚举并读取全部历史日志；额度内容没有变化时 UI 不重复更新。
5. 收起期间不应因日志变化执行周期排行查询或写入 SQLite。展开、标签点击或手动刷新属于用户明确触发，应单独记录。

## 按需周期刷新

分别执行并记录一次：

- 从收起态悬停展开：应切到今日，只刷新今日。
- 点击近 7 日、本月、累计：每次只查询目标周期。
- 重复点击当前标签：仍执行一次目标周期刷新。
- 固定展开后静置：统计不自行刷新。
- 点击手动刷新：更新当前周期和额度。

加载过程中旧数据应保留，收起取消普通周期查询后，首次后台历史索引仍可继续完成。

## UI 响应时间

运行 `scripts\capture-ui.ps1`，以真实指针移出前为计时起点，记录窗口恢复为 80×80 的耗时。目标范围为 0～150 毫秒。固定、拖动或关闭自动收起时不应用该目标。

当前 [`ui-audit.json`](screenshots/ui-audit.json) 记录 Vision Glass 界面
16/16 真实鼠标验收通过，实测移出后 65 毫秒恢复为 80×80，落在 0～150 毫秒
目标内。报告还会把真实指针移到一个 `WeeklyQuotaDay_*` 日期节点，确认悬浮提示
出现期间进程未退出且主窗仍为 420×540，从而覆盖只读绑定崩溃回归；同时记录圆形
收起态、圆角展开态、单一玻璃设置页、周额度 Overlay、边缘展开和锚点恢复。该交互
耗时只对报告内的 EXE SHA-256 有效；后续重新发布后应整套重跑。若在锁屏或安全
桌面运行脚本，应把指针事件受阻视为环境无效并在解锁后重试。
