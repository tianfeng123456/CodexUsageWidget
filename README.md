# Codex 用量悬浮窗

[![最新版本](https://img.shields.io/github/v/release/tianfeng123456/CodexUsageWidget?label=%E6%9C%80%E6%96%B0%E7%89%88%E6%9C%AC)](../../releases/latest)

当前稳定版：**v1.2.1**。中文说明见本页，英文说明见 [README.en.md](README.en.md)。

一个完全在本机运行的 Windows 11 桌面小组件，用来查看 Codex 剩余额度和各任务的 Token 消耗。应用采用 WPF、.NET 8、SQLite 和 MVVM，发布为 Windows x64 自包含单文件，使用者无需预装 .NET。

> 本项目是非官方社区工具，与 OpenAI 不存在隶属、赞助或背书关系。

## 下载

普通用户请从 [GitHub Releases](../../releases/latest) 下载
`CodexUsageWidget.exe`。它是 Windows x64 自包含单文件，无需预装 .NET。
当前 EXE 尚未进行代码签名，因此 Windows SmartScreen 首次运行时可能显示提醒；
请核对 Release 页面公布的 SHA-256 后再运行。

仓库中的 `dist\CodexUsageWidget.exe` 只由本地构建产生，不进入 Git 历史。
版本变化见 [CHANGELOG](CHANGELOG.md)。

## 界面

待机样式可在设置的“外观 → 待机样式”中选择 32×32 微光、80×80 圆环或
208×80 胶囊。微光不显示数字，只用静态光圈与状态色表达剩余额度；圆环和胶囊
保留剩余百分比及轻量状态信息。鼠标移入后会直接展开为
420×540 完整面板，不再经过短暂的中间过渡态；面板可固定展开，或在鼠标移开后
立即收起为所选样式。待机组件始终作为位置锚点：右侧空间足够时面板向右展开，
否则向左展开；下方空间不足时向上展开，收起后组件回到原位。新安装默认使用圆环。

收起态圆环底部的心电波不是独立装饰，而是进度轨道的一段：未走到时保持暗色，
进度经过圆环底部时才会沿波形逐段点亮。

胶囊的状态文案和波形颜色会随剩余额度变化：70% 及以上为“额度充足”，
30%～69% 为“用量平稳”，10%～29% 为“额度偏低”，1%～9% 为“即将用尽”，
0% 为“已用尽”；首次读取时还会显示“正在同步”或“等待数据”。微光、圆环与胶囊
共用同一套判定，状态只在既有额度事件发生时重新计算，不增加轮询。胶囊的
百分比、标题和状态色分别使用浅色 / 深色专属高对比配色；胶囊卡片不使用会产生
方形裁切的阴影，桌面快照本身也由独立圆角表面裁剪，圆角外保持完全透明。

不要把不同哈希批次的截图当作同一份最终验收。综合验收还会把真实鼠标移到

界面只保留一套 Vision Glass 轻玻璃视觉，不再提供皮肤选择器。它随
System / Light / Dark 主题切换为浅色或深色玻璃，但布局、交互与材质语言保持
一致。浅色与深色分别使用独立的辅助文字对比度，底部汇总数字采用正常字重，
在明暗复杂的桌面背景上仍保持清晰。

玻璃材质不启用 Windows 原生 Acrylic。窗口只在加载、收起/展开、主题或 DPI
变化、拖动结束和手动刷新等明确事件发生时，截取一次组件下方的桌面画面；快照在
后台线程执行软件模糊，完成后作为冻结图像填充到 WPF 圆形或圆角表面。它没有
持续抓屏、实时背景模糊、渲染循环或常驻动画。

“外观”中提供 `0%～100%` 的玻璃透明度滑杆：`0%` 为完全不透明，`50%` 精确对应
原始玻璃效果，也是新安装的默认值；数值越高，主玻璃背景越透明。`100%` 对应旧版
`99%` 的安全端点，内部仍保留非零的材质与命中层，以保证窗口元素、拖动和鼠标识别可靠；文字、
图标、进度线和状态色始终保持原有不透明度。透明度修改在保存设置后应用；设置页不提供
模拟样片，避免样片材质与实际桌面背景产生误导。

待机态和展开态都不绘制额外的矩形底板或装饰边框。32×32 微光只保留透明命中区
与状态光圈，80×80 圆环由圆形表面定义，208×80 胶囊和 420×540 面板由各自的
圆角表面定义，窗口其余区域保持逐像素透明；
快照只填充到对应形状内部，不会在透明区域留下方形毛玻璃底。

顶部的“周已用”与七日微型折线是全局状态，不属于某一个 Token
统计页，因此切换今日、近 7 日、本月或累计后都不会留下空白区域。点击它会在
同一个 420×540 窗口内打开七日详情，不创建额外弹窗：

![七日周额度每日消耗](docs/screenshots/weekly-quota-overlay.png)

面板包含四个统计页：

- **今日**：本地自然日。
- **近 7 日**：从当前时刻精确向前滚动 168 小时。
- **本月**：本地时间当月 1 日至当前。
- **累计**：本机仍保存或已经被本组件索引的历史日志。

每页最多显示十行：前 9 行是真实任务；任务超过 9 个时，第 10 行显示无法展开明细的“其他”。底部汇总输入、输出、缓存输入、推理输出和总 Token，且满足“前 9 + 其他 = 总计”。子代理、审批代理及并行代理的消耗会归入对应的根主任务。

Token 数值会跟随界面语言切换单位，最多保留两位小数并移除无意义的末尾零：

- 简体中文：小于 1 万显示完整整数；之后依次使用“万 / 亿 / 万亿”，例如
  `9,876`、`6.03亿`、`1.01万亿`。
- English：小于 1,000 显示完整整数；之后依次使用 `K / M / B / T`，例如
  `9,876` 会显示为 `9.88K`，`602,820,000` 会显示为 `602.82M`。

## 使用

双击 `dist\CodexUsageWidget.exe` 即可运行。应用支持按需增量刷新、置顶、立即自动收起、Codex Home 选择、窗口位置及当前标签页持久化；同一时间只允许一个实例运行。

主题提供三种模式：

- **跟随系统（System）**：新安装的默认选项；Windows 明暗模式变化时通过系统事件同步，不进行轮询。
- **浅色（Light）**
- **深色（Dark）**

语言也提供三种模式：

- **跟随系统（System）**：Windows UI 区域为任意 `zh-*` 文化时使用简体中文，
  其他区域统一使用 English。
- **简体中文**
- **English**

设置页按使用频率依次排列为“外观 → 常驻行为 → 数据来源 → 维护”。主题、语言和
待机样式以及玻璃透明度都位于最前面的“外观”分组；待机样式可选：

- **微光（Glow）**：32×32，无数字，只显示剩余额度光圈，桌面占用最小。
- **圆环（Circle）**：80×80，默认显示百分比。
- **胶囊（Capsule）**：208×80，在百分比之外常驻显示简短状态。

切换待机样式不会增加轮询、日志读取或 SQLite 查询；三种样式在静默时采用相同的
事件驱动刷新策略。

“常驻行为”提供“息屏或锁屏时暂停后台监控”，新安装默认开启。程序通过 Windows
显示、电源与会话事件进入休眠，不轮询屏幕状态；息屏、锁屏或系统休眠后会停止
文件监听、额度尾读和页面查询。只有在屏幕重新点亮且会话已经解锁后才恢复监听，
并合并为一次最新额度校准；四个 Token 周期和周额度历史仍等待用户明确操作后
刷新。休眠期间 Codex 写入的日志仍保留在磁盘上，后续按需增量处理，不会因为
暂停本组件而丢失。

切换语言并保存后，主窗口、设置窗口、系统托盘、提示文字、日期格式和 Token
单位会在当前进程内同步更新，不需要重启。语言切换只替换内存中的小型字符串
资源，不会扫描日志、刷新统计、查询 SQLite 或重建文件监听；对常驻资源占用的
影响可以忽略。任务名称来自本机 Codex 日志，应用会原样保留，不做机器翻译。

三种模式与全局周额度浮层通过 `capture-themes.ps1` 一并验收。当前
[`theme-audit.json`](docs/screenshots/theme-audit.json) 记录 System / Light / Dark
均为 PASS，三种模式均识别到 7 个周额度日期元素，且浮层打开前后顶层 HWND
数量保持 `1 → 1`。目录中的
[深色](docs/screenshots/theme-dark.png)、[浅色](docs/screenshots/theme-light.png)、
[跟随系统](docs/screenshots/theme-system.png) 及对应 Overlay 截图均由该次验收生成。
报告自带被测 EXE 哈希，结论只适用于该哈希；后续构建改变哈希时应整套重跑。

设置窗口的逻辑尺寸为 460×590。旧版配置仍可兼容读取，延迟输入不再出现在设置界面。

系统托盘菜单提供五项操作：

- 显示/隐藏
- 立即刷新
- 设置
- 开机启动
- 退出

托盘图标和 EXE 图标采用透明背景的原创六瓣交织空心线稿；加粗的高对比轮廓在
16～20 像素下仍保持清晰，不复用第三方品牌标识。托盘线条会随系统明暗模式切换
深色 / 亮色，右上角状态点按剩余额度切换绿、黄、橙、红；EXE 内置
16～256 像素多尺寸图标，避免小尺寸缩放发糊。

开机启动默认关闭，只有用户主动切换后才会写入 Windows 启动项。

## 数据来源与统计口径

程序只读访问所选 Codex Home 下的：

```text
sessions\**\*.jsonl
archived_sessions\**\*.jsonl
session_index.jsonl
```

- 总 Token = 输入 Token + 输出 Token。
- 缓存输入已包含在输入 Token 中，推理输出已包含在输出 Token 中，均不会重复计入总量。
- 每个日志文件对五个累计字段分别维护单调高水位，只记录超过既有高水位的增量；并发会话产生的轻微旧快照不会被误判成整段重置。
- 文件增长继续增量处理；截断、等长改写和文件替换由文件连续性校验识别，随后从新文件内容建立全新高水位。
- 子代理日志可能在首个顶层 `inter_agent_communication_metadata` 之前复制根任务的历史事件；这段继承回放不会重复计入。标记之后的首轮和后续用量会正常保留，后续同类标记也不会再次截断统计。
- 缺少 `parent_thread_id` 的根级子代理分叉会与来源任务逐条比较累计 Token 序列，并剔除最长一致前缀；复制历史中即使包含触发标记，也不会提前结束去重。来源任务尚未入库时，该分叉会等待后续刷新，期间不写入未经确认的用量。
- 使用旧累计算法的索引会在下一次由用户明确触发的统计刷新中执行一次完整重算；已经使用高水位算法的索引只检查首行元数据，并仅重算受影响的根级子代理分叉。启动和收起静默态不会为此扫描历史日志。迁移版本与高水位检查点会持久化，后续只处理增量。
- “累计”页展示本机当前 Codex Home 中仍可读取的日志累计。Codex 账户 Profile 的服务端覆盖范围和刷新节奏可能不同，两者不保证逐时完全一致。
- 剩余百分比来自本地日志最新的 `rate_limits`；没有该字段时显示 `--`，不会根据累计消耗猜测额度。
- 周额度详情只读取精确的 `limit_id=codex`、10,080 分钟窗口。七根柱和折线表示各本地自然日从日志中观测到的周额度消耗百分点，不再把昨天的日末累计值继承给今天。
- 每个服务端重置周期独立维护单调高水位，只累计高水位的上升量；相差 60 秒内的 `reset_at` 会归并为同一逻辑周期。每天采用当天最后一次有效额度观测所属的时间线，并只计算该时间线从日初到日末的高水位增量，因此不会把并行时间线重复相加，也不会把整个周期累计值算到今天。并发会话晚到的旧快照、窗口重置造成的下降也不会被误算成当日消耗。较前日变化比较的是两天各自的消耗量，而不是累计周已用值。
- 已存在于本机日志或索引中的历史观测可以直接重建；后续观测会在用户明确刷新统计或打开周额度详情时增量写入本地索引。缺少观测或缺少可靠起点的日期会显示为空白或仅代表可观测部分。
- 启动时只校准一次最新额度；首次运行会在单线程后台建立一次历史索引，之后只处理新增或变化的统计内容。
- 收起态没有固定 30 秒轮询，也不会周期性查询排行榜或写入 SQLite。日志变化只触发额度尾读：静默约 1.5 秒后处理，持续写入时最多约每 3 秒处理一次；额度未变化时不更新 UI。
- 启用息屏暂停后，程序通过系统事件进入应用级休眠；休眠态停止 watcher、尾读、页面查询及相关 UI 更新。亮屏并解锁后只重建监听并执行一次有界额度校准，完整统计继续按需刷新。
- 悬停展开会切回“今日”并只刷新今日；点击任一周期标签（包括重复点击当前标签）会刷新该周期；手动刷新会更新当前周期和额度。
- 七日周额度历史仅在点击顶部入口时查询；收起、悬停展开、切换 Token 标签以及额度 watcher 均不会自动查询它。
- 固定展开时统计不会自行刷新，仍由标签点击或手动刷新触发；额度可继续随日志事件更新。

## 隐私与本地存储

应用不联网、不上传数据，也不打开 `auth.json`、密码或访问令牌。为了识别 Token、
额度和会话元数据，解析器会在本机顺序读取 JSONL 行，但不会提取、保存或上传用户
提示词与聊天正文。SQLite 只保存统计所需的任务标识、标题、时间桶、Token 数值和
文件增量状态。

无法在界面内安全处理的异常会尽力写入本机
`%LocalAppData%\CodexUsageWidget\diagnostics.log`；文件达到 1 MiB 后轮转，
不会上传。诊断日志写入失败也不会影响应用继续退出或恢复。

设置与索引位于：

```text
%LocalAppData%\CodexUsageWidget
```

每个 Codex Home 使用规范化路径的哈希生成独立数据库，例如：

```text
usage-index-<home-hash>.db
```

因此切换不同 Home 时不会混合统计。

## 构建

构建环境需要 Windows 10/11、PowerShell 5.1 或更高版本，以及 .NET 8 SDK。

项目提供本地构建脚本：

```powershell
.\scripts\test.ps1
.\scripts\build.ps1
.\scripts\measure-idle.ps1
.\scripts\capture-ui.ps1
.\scripts\capture-themes.ps1
.\scripts\audit-localization.ps1
.\scripts\audit-idle-styles.ps1
.\scripts\generate-app-icon.ps1
```

`build.ps1` 会先运行测试，再发布 `win-x64` 自包含单文件到 `dist`。具体测试数量、最终包哈希和本机实测结果以当次 [验证报告](docs/validation-report.md) 为准；低资源验收方法见 [性能验证](docs/performance-report.md)。

`audit-localization.ps1` 使用 UI Automation 的稳定 `AutomationId` 打开设置并完成
“简体中文 → English → 简体中文”的双向切换，验证英文关键文字真实可见，同时
确认设置已持久化；它不依赖屏幕坐标，结束后会恢复原设置并输出
`docs/localization-audit.json`。

`audit-idle-styles.ps1` 会备份并恢复原设置，分别启动微光、圆环和胶囊待机态，验证
`32×32 / 80×80 / 208×80 → 420×540` 的悬停展开没有可观测中间窗口尺寸，并输出
`docs/idle-style-audit.json` 及三种样式的验收截图。静默性能也可分别执行：

```powershell
.\scripts\measure-idle.ps1 -CollapsedMode Glow
.\scripts\measure-idle.ps1 -CollapsedMode Circle
.\scripts\measure-idle.ps1 -CollapsedMode Capsule
```

## 已知限制

- “累计”仅覆盖本机已保存或曾被本组件索引的日志，不代表其他设备、服务端账单，或已删除且从未索引的历史。
- 剩余额度依赖本地 `rate_limits` 事件，不能推导 Codex 未公开的固定 Token 上限。
- 周额度是日志中的滚动窗口观测，不等同于服务端账单；每日消耗只重建日志实际观测到的高水位增量。日志缺失、长时间无观测或缺少周期起点时，程序不能恢复未被记录的消耗。
- Codex 日志是应用内部格式，未来字段变化可能需要更新解析器；遇到异常可在设置中重建索引。
- 首次索引时间取决于本机日志体量与磁盘性能；界面会按已处理日志字节显示
  0～100% 的真实进度，并区分准备、读取、汇总和未完成状态。
- 文件监听发生漏事件或程序处于息屏 / 锁屏休眠时，界面额度可能暂时滞后；启动、亮屏解锁、系统恢复、悬停展开和手动刷新会执行校准，不会因此恢复固定轮询。
- 内置界面语言目前为简体中文和 English；“跟随系统”对其他语言区域回退到
  English。
